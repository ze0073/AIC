# 视界 · AI 网站质量测试平台

当前构建版本为 `0.9.0-SNAPSHOT`（网站部署、检测与修复的本机开发预览）。用户可以自助注册，上传网站或连接 Git 仓库，在隔离环境中部署和检测，确认源码修复后自动部署并复测，再确认更新长期托管的网站。保留 V0.5 静态检测、V0.6 报告快照及 V0.7 / V0.8 智能任务与历史数据。实施与验收记录见 [V0.9 实施记录](md/视界-V0.9.0-实施记录.md)。

## 视界向导：全站数字人引导

登录后，右下角二维机器人提供部署、检测、修复、报告和功能介绍五类目标；移动端使用底部抽屉。首次欢迎可以跳过，之后默认收起，未完成流程可继续。

- **带我操作**：打开原页面，通过控件高亮和文字步骤引导；控件未加载时保留文字说明。
- **帮我办理**：填写业务卡片，审阅冻结的网站、版本、配置与差异，再点击独立的确认按钮。聊天中的“确认”不会执行操作。
- 个人流程与偏好保存在服务端，刷新、切换页面和操作方式后可继续；执行复用现有部署、检测、修复复测和报告服务。
- 规则模式不依赖外部模型。Qwen 配置可用时，用户同意发送脱敏摘要后增强理解与解释；失败时回到规则流程。
- 语音由用户主动播放浏览器中文声音；关闭面板或退出账号时停止。停止、回退、删除继续在网站工作区办理。

实施范围和验证证据见 [数字人向导实施与验收](md/视界-数字人向导-实施与验收-2026-10-04.md)。隔离验收脚本为 `tools/verify-guide.mjs`，使用独立数据库、存储和端口；结果写入 `output/guide/`。

## V0.9：部署我的网站

1. 登录或选择“创建账号”，填写用户名、密码和图片验证码。注册不依赖邮件服务。
2. 打开“我的网站 → 部署我的网站”，选择“检测修复环境”或“长期托管”。
3. 上传 ZIP / HTML，或连接 GitHub、GitLab、Gitee 的 HTTPS 仓库。私有令牌通过专用表单填写；每次主动拉取固定 Git 提交，不向仓库推送。
4. 平台自动识别静态网页、React / Vue、Node.js、Java / Spring Boot（Maven）、Python；其他项目可附带 Dockerfile 和 `shijie.json` 运行配置。确认是否需要 MySQL 或 PostgreSQL，复杂设置在“高级运行设置”里。
5. 点击“部署并自动检测”。工作区实时显示导入、构建、启动、健康检查及检测结果；断线后轮询恢复。可以取消、重试及查看经过脱敏的日志。
6. 从检测问题打开修复，确认源码差异后生成新版本，平台自动部署并覆盖原范围复测。原问题未消失、页面不可用、结果缺失或新增高风险均不能通过验证。
7. 长期托管需要单独点击“确认更新网站”。新版本通过检查后切换入口；发布完成后停止对应测试环境，保留源码、数据库副本及检测证据。应用版本可回退，数据库不会随应用回退或被删除。

### 本机运行与隔离

- 管理地址：`http://127.0.0.1:8080`；网站使用独立 `s-网站ID.localhost:8090` 地址，测试版本使用独立且需要授权的预览地址。管理会话不会转发给用户网站。
- 项目启动脚本同时启动独立部署执行器（健康检查端口 `18091`）。重启时恢复排队任务、核对容器及实际访问端口；中断任务明确标记失败并提供重试。`start-hosting-worker.ps1` 可单独恢复执行器；`status-local.ps1` 查看状态，`stop-local.ps1` 停止平台和执行器并保留数据卷。
- Windows 启动脚本会为 Docker 客户端继承系统中已启用的 HTTP / HTTPS 代理，显式环境变量或 `.env` 中的 `HTTP_PROXY`、`HTTPS_PROXY` 优先；本机管理与 `.localhost` 网站入口绕过代理。修改代理后需重启部署执行器。启动时优先使用本机已有的 `busybox:1.37`，仅在缺失时下载，避免网站构建成功后因重复下载辅助镜像而失败。
- 仓库根目录没有运行配置时，可识别直接子目录中的单个 Maven 后端及 Vite 前端，例如 `ai-match-server/` 与 `ai-match-frontend/`，分别构建并通过同一网站地址访问；多个候选模块需要用 `shijie.json` 指定。子目录内仅复制预先构建 JAR 的 Dockerfile 不会取代 Maven 源码构建。嵌套静态入口使用站内相对跳转，保留预览地址和端口。镜像仓库令牌或元数据下载遇到 TLS 超时、EOF 或连接重置时最多尝试 3 次；源码编译失败直接报告。
- 默认每账号 3 个项目、2 个运行环境、1 个构建任务；平台管理员在“账号管理”调整额度。项目管理员仅管理本项目成员，不会创建平台账号。新账号不会自动加入旧项目。
- 右上角用户菜单进入“用户中心”（`/profile`）：修改显示名称、联系邮箱、手机号和简介，上传或移除个人头像，修改登录密码并查看使用额度。联系方式仅作资料，不用于登录或找回密码；用户名、平台身份和额度为只读。头像支持 2 MB 以内的 PNG/JPEG，保存为居中裁剪的 256×256 PNG；个人资料和头像仅本人可读取和修改。
- 测试环境默认 24 小时，长期托管持续运行直到停止。停止后仍可下载源码和数据备份；完整备份包含 `/data` 中的网站文件归档和数据库 SQL（若使用数据库）。文件归档上限 100 MB、60 秒；运行中的文件可能继续变化。
- 用户应用使用独立内部网络、数据库及数据卷；可信访问适配器提供入口。应用容器不挂载宿主目录或 Docker 接口，使用普通用户、只读根目录、CPU / 内存 / 进程限制。可写路径为 `/tmp` 和 `/data`。
- 构建使用独立 BuildKit 和公网地址校验的下载代理。Docker Desktop 的可信网络代理可用于转发；内网、宿主地址及特权构建请求继续被拒绝。Windows Git 使用系统信任证书集合，保持 TLS 校验。
- 运行环境变量和仓库凭据加密保存，运行密钥不进入源码包、构建上下文或 AI 请求。ZIP 不包含 `.git`、`node_modules`、`.env`、`.npmrc`、`.netrc` 或 `.pypirc`；源码限制 20 MB 压缩、100 MB 解压、500 个文件。
- 业务写入、上传、主动安全和负载测试在独立数据库副本中执行。正式数据库不接受这些检测；数据库结构变化需要单独迁移。
- 公网域名、HTTPS、计费和高可用进入后续版本。当前 `.localhost` 环境使用 HTTP，检测可能提示未启用 HTTPS；应按本机用途理解这个结果。

本机验收明细和已知边界见 [V0.9 实施与验收记录](md/视界-V0.9.0-实施记录.md)。当前 Windows 设备已实际听到向导中文播报；私有仓库凭据流程已实现，授权仓库的端到端导入仍待使用者在产品表单中提供真实只读凭据。

## 本机 8080 快速体验

首次构建会安装 Chromium，并下载固定版本的 ZAP 与 k6 镜像；已有依赖时可跳过对应步骤：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-local.ps1
powershell -ExecutionPolicy Bypass -File .\start-local.ps1 -SkipNodeInstall -SkipBrowserInstall -SkipToolImages
```

平台默认管理入口为 http://127.0.0.1:8080。本地首次管理员默认用户名为 `admin`、密码为 `change-me-on-first-run`。首次登录后可从右上角用户菜单选择“修改密码”；`APP_INITIAL_ADMIN_PASSWORD` 只在空数据库首次初始化时生效，不会修改已存在账号。平台与数据库默认只监听 `127.0.0.1`；共享部署必须显式设置 `SERVER_BIND_HOST`，在首次启动前设置安全的 `APP_INITIAL_ADMIN_PASSWORD` 与 `APP_CREDENTIAL_KEY`，并配置可信的网络边界；本机版本提供用户名、密码及验证码注册。

进入项目卡片的“质量测试中心”后：

1. 登记允许测试的 Origin、DNS 地址和路径范围；内网目标也必须明确登记。
2. 创建版本化测试套件；可在测试中心编辑并发布新版本，配置 VU 阶梯、每阶段时长、速率上限、P95 和错误率阈值。默认负载为 1、5、10 个虚拟用户，每阶段 20 秒，P95 ≤ 1000ms、错误率 < 1%。
3. 启动统一测试。前端页面、主动安全和负载模块使用同一单线程队列串行执行。
4. 在运行详情查看模块状态、页面指标和测试图表；前端指标、安全结果、P50/P95/P99、错误率与时间序列均保留明细表。高级 JSON 证据会突出异常行并给出定位注释，也可从同一不可变快照导出 PDF/JSON。
5. 在“修复任务、案例与回归”中管理任务、规则/AI 原因解释、知识案例和可启停的每日回归计划；确认或驳回候选改为可选审阅，不阻塞发布。

### 单智能体在线检测（预览）

在项目“质量测试中心”选择“智能测试”，可选 `RULE`（默认、离线可运行、无模型请求）或 `QWEN`（须配置百炼并同意发送脱敏摘要）。先选择已登记目标和套件，可选同项目、同目标、同套件版本且至少有一个完整模块的历史任务作为基线。确认页展示执行模块、只读接口、负载和基线缺失项；确认后记录每次决策、证据引用、真实运行和指标差值。任务页通过实时事件展示当前模块、步骤、完成比例与最新状态，连接中断时自动轮询恢复；运行中可取消。

智能体每项任务最多执行 3 个模块（每个一次），最多进行 8 次决策，最长运行 15 分钟。安全模块仅执行 GET/HEAD/OPTIONS 用例，不运行上传、写接口或主动漏洞扫描。前端浏览器默认阻止写请求；只有目标已授权写测试且确认计划明确列出交互步骤时，才在这些步骤执行期间允许写请求。性能负载使用确认页展示的既有套件参数。自动候选不会被模型自动确认为漏洞；人工审阅为可选能力，智能体不应用修复。

检测目标中不要填写 Token/Cookie；凭据通过专用表单登记。Qwen 后续决策必须引用真实观察步骤；模型等待期间取消或执行者失去成员权限，不再启动后续检测。任务结束时固定 `schemaVersion=0.7.0` 复盘摘要，后续可选审阅变化不改写旧摘要。既有边界测试见 [智能体边界验收](md/视界-智能体边界验收-2026-09-27.md)。

### 对话式项目助手（开发预览）

从首页或项目质量中心打开“项目助手”。`RULE` 模式可离线查看项目概况、生成智能检测计划和查询任务状态；`QWEN` 模式须先同意发送脱敏摘要。助手只引用已经登记的目标、套件版本和可选历史基线，不会根据聊天内容自行创建授权范围。

聊天中输入“确认”“开始”或“执行”不会触发检测。生成计划后，页面会显示冻结的执行范围、计划哈希和待确认操作，只有项目成员单独点击计划卡片上的“确认执行”才会启动真实任务；也可以取消计划。重复确认使用同一执行回执，不会重复启动。Token、Cookie、密码或密钥类文本会被脱敏并阻止生成操作。

本版本的助手尚不代替凭据登记、主动扫描授权、上传/写测试和修复操作页面。漏洞候选不能由模型自动确认；项目成员可以跳过审阅，候选会保持“未自动确认”并照常进入证据与报告。

### V0.8.0 智能引导工作区（开发预览）

进入项目助手后，系统会从已登记资源中推荐最近更新的网站、当前检查方案和最近一次具有完整证据的同范围任务，并自动填入通俗的日常体检目标。用户仍可在生成计划前更换任一选项；系统不会根据聊天内容创建新的授权范围。

确认冻结计划后，页面留在同一工作区，通过实时事件和轮询兜底展示模块进度、取消状态与证据保存情况。任务结束后，新的只读洞察接口会聚合同网站、同方案最近 8 次智能任务，显示问题数和 P95 趋势，并生成带优先级、建议负责人、证据说明、处理步骤和防复发措施的行动清单。趋势遇到部分完成、无有效性能样本或范围不可比时会明确标为受限，不把缺失值或执行结束状态解释为质量通过。

V0.8.0 沿用现有运行、问题工单、成员和回归数据，不新增数据库迁移。旧任务可按现有证据动态生成洞察；旧不可变报告及其哈希保持不变。

ZAP 只有在目标明确授权、套件登记了可主动扫描的 GET 接口和查询参数后才会运行，策略只启用 SQL 注入与反射型 XSS。凭据使用 AES-GCM 加密并绑定项目、目标、凭据 ID 与 Origin，接口永不回传明文。工具镜像不挂载 Docker Socket，工具缺失、崩溃、超时或取消时，其他模块结果仍保留。每日回归默认不运行主动扫描、上传或负载；这三项须分别明确启用。

## 独立校园报名演示应用

演示应用使用独立 MySQL 数据库，平台通过真实请求判断结果，不读取模式开关：

```powershell
cd demo-app
mvn package
cd ..
$env:DEMO_MODE='defective' # 可改为 fixed 或 regression
docker compose --profile demo up -d --build demo-mysql campus-demo
```

访问 `http://localhost:8091`。`defective` 提供可控 SQL 注入、反射型 XSS、权限、上传校验和慢接口正例；`fixed` 修复对应问题；`regression` 只恢复权限缺陷，用于验证复发关联。`/api/scope-redirect` 与 `/api/unavailable` 分别用于范围边界和高错误率保护验收，不是业务缺陷。演示凭据采用 `demo-user-a`、`demo-user-b`、`demo-admin` Bearer Token，可在质量中心按目标分别登记；仅供本机演示，不得用于真实认证。上传测试仅使用唯一无害标记文件，接受文件不等同于可执行木马。

数据库与故意带缺陷的演示应用默认只绑定 `127.0.0.1`。若要让 Docker 中的 ZAP/k6 访问演示应用，只在隔离实验环境把 `DEMO_BIND_HOST` 临时设为容器可达的**具体宿主机私有接口地址**，并用同一地址登记目标；不要绑定 `0.0.0.0`。实验结束后恢复回环绑定，不要将缺陷模式开放到局域网或公网。

## 本地启动

Windows 推荐在项目根目录执行一条命令：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-local.ps1
```

脚本会创建本地 `.env`、启动 MySQL、安装/构建前端、安装 Chromium，并在 `http://localhost:8080` 启动包含前端页面的应用。依赖已安装时可增加 `-SkipNodeInstall -SkipBrowserInstall`。

本机运行环境已安装在项目的 `.runtime` 目录中。由于当前 Windows 用户的 `AppData` 启用了不可用的 EFS 加密，`start-docker.ps1` 会仅为 Docker 进程使用 `.runtime` 下的独立配置目录，不会修改系统的全局 `AppData`。首次启用 WSL/虚拟机平台后必须重启一次 Windows。

如只需启动或检查 Docker：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-docker.ps1
```

也可手动启动：

1. 复制 `.env.example` 为 `.env`，仅在本机填写密码。
2. 启动数据库：`docker compose up -d mysql`。
3. 安装扫描浏览器：进入 `backend` 后执行 `mvn exec:java -Dexec.mainClass=com.microsoft.playwright.CLI -Dexec.args="install chromium"`。
4. 启动后端：进入 `backend` 后执行 `mvn spring-boot:run`。
5. 启动前端：进入 `frontend` 后执行 `npm install` 和 `npm run dev`。

开发模式浏览器访问 `http://localhost:5173`。生产构建时先在 `frontend` 执行 `npm run build`，再构建后端；Maven 会将前端产物一并打入 Spring Boot JAR，访问地址为 `http://localhost:8080`。

默认开发数据库配置与 `docker-compose.yml` 一致，可由环境变量覆盖。上传文件和扫描工件写入 `APP_STORAGE_ROOT`，该目录不得提交到仓库。

## 启用 AI 语义分析（P1）

默认 `AI_ENABLED=false`，因此 P0 始终可离线运行。若要启用百炼 Qwen 视觉分析，请仅在本机 `.env` 或部署环境变量中填写：

```dotenv
AI_ENABLED=true
AI_PROVIDER=qwen
AI_BASE_URL=https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
AI_API_KEY=你的百炼密钥
AI_MODEL=qwen3-vl-plus
```

前端扫描页会展示数据发送提示，用户确认后才会发送最小证据；不会发送完整项目、数据库数据、密钥或本地路径。R001–R003 使用问题元素的裁剪截图，R009 只发送最多 4 组局部冲突区域拼图和最多 12 个元素摘要。AI 对 R009 只能解释和提出可选审阅建议，不能确认风险、改变候选生成结果或生成补丁。服务未配置、未授权、超时或返回不合法 JSON 时，离线扫描仍可完整运行，可选审阅也不依赖模型。

## V0.4.0 交互路径与阅读顺序复核

- 每个启用 R007 的页面保存正向 Tab 和反向 Shift+Tab 轨迹，单向最多 30 步；记录选择器、角色、可访问名称、`tabindex`、坐标与焦点样式，并标记循环、截断、无目标和疑似不可见焦点。
- R009 最多分析 80 个可见语义块和交互元素，仅对 `horizontal-tb` 的 LTR/RTL 页面生成启发式候选。候选默认为 `NEEDS_REVIEW`，未确认前不进入高/中/低统计和内部风险分。
- 交互分析页 `/scans/{scanId}/interaction` 同时提供编号截图和文字表格，可切换焦点方向、DOM 序列与视觉序列。
- 可选审阅支持记录风险、驳回候选和保持候选，不参与发布门槛。记录与驳回按项目、规则、页面、标准化选择器和证据指纹精确复用；源码、名称、相关样式或顺序变化后不会复用。
- 报告明确区分确定性问题、已记录风险、自动候选和已驳回结果，并记录轨迹摘要、可选审阅历史及结论复用来源。

## V0.4.0 保留的 AI 候选修复闭环

对置信度为高或中的 R001 图片和 R003 按钮/链接建议，问题详情页允许用户编辑候选文本后生成最小属性补丁。R001 支持用户明确选择装饰图并写入 `alt=""`；R003 只写入 `aria-label`。系统使用浏览器选择器和 Jsoup 源码位置共同定位，只修改目标开始标签；动态元素、重复选择器、已有目标属性或无法确认源码位置时拒绝生成补丁。

应用 AI 候选补丁必须先审阅 Diff 并明确确认，随后创建不可变的 `AI_PATCH` 新版本并自动沿用原扫描的页面、规则和键盘配置复测。复测只确认基础规则是否消失，不再次调用 AI；报告会记录最终文本、模型来源、确认时间，并明确语义由用户确认，不代表完整 WCAG 验证。

## 测试与打包

```powershell
cd frontend
npm test -- --run
npm run build

cd ..\backend
mvn -Dplaywright.tests=true test package
```

第二条 Maven 命令会启用真实 Chromium 测试，并将前端、数据库迁移和内置字体打入 `backend/target/accessibility-0.8.0-SNAPSHOT.jar`。V0.8.0 的智能洞察复用现有数据表；Flyway V9–V11 继续保存 Agent 模式、基线关联及项目助手会话/消息/待确认动作，历史扫描和已有报告保留。

`verify-demo.ps1` 是历史静态演示自动化脚本，会创建独立示例项目并保存可选审阅记录，不作为正式发布门槛。当前智能体边界检查可运行 `node .\tools\verify-agent-boundaries.mjs`，默认使用隔离数据库和 18081，不调用云端模型；详情见上面的边界验收记录。

## 支持边界

静态流程扫描 HTML/CSS/JavaScript，不执行上传项目中的命令或构建脚本。在线流程只检测经项目管理员登记授权的 Origin、DNS 地址与路径；不支持任意 URL 随意扫描，所有重定向仍受范围校验。内部风险分不代表完整 WCAG 合规或全面安全认证。

PDF 报告内置 Noto Sans SC 字体，可在离线 Linux/Windows 环境显示中文。字体依照 SIL Open Font License 1.1 分发，许可证位于 `backend/src/main/resources/fonts/OFL-NotoSansSC.txt`。
