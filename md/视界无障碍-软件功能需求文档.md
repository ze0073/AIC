## 1. 产品概述

### 1.1 产品简介

“视界无障碍”是一款面向网页开发和测试人员的 AI 软件。用户上传网页项目后，系统通过网页结构分析、浏览器自动化、视觉分析和 AI 语义判断，识别网页中的无障碍问题，并为部分问题生成可审阅、可回滚、可复测的代码修复方案。

### 1.2 核心流程

```text
创建项目
   ↓
上传网页项目
   ↓
启动扫描
   ↓
基础规则检测 + 浏览器交互检测 + AI 语义分析
   ↓
查看问题和证据
   ↓
生成修复方案
   ↓
人工确认并生成新版本
   ↓
自动复测
   ↓
查看前后对比并导出报告
```

### 1.3 第一版功能边界

第一版支持：

- 上传 ZIP 网页项目或单个 HTML 文件；
- HTML、CSS、JavaScript 静态网页；
- 单页或由用户显式选择入口文件的少量多页网站；
- Chrome/Chromium 浏览器渲染；
- R001–R009 共 9 类无障碍检测与启发式复核候选；
- AI 风险解释、低风险模板修复和待人工审阅的修复建议；
- 修复前后对比和 PDF 报告。

第一版不支持：

- 需要登录、验证码或复杂后端状态的网页；
- 原生移动应用；
- 视频、音频和复杂多媒体的完整无障碍评测；
- 自动修改生产环境代码；
- 声称网站完全符合 WCAG 标准；
- 自动抓取任意公网 URL 或执行项目提供的构建、安装和系统命令。

## 2. 用户角色与权限

### 2.1 用户角色

| 角色 | 权限 |
|---|---|
| 普通用户 | 创建项目、上传文件、发起扫描、查看结果 |
| 开发者 | 查看代码、生成修复、确认修复、回滚版本 |
| 测试人员 | 管理扫描任务、复测、导出报告 |
| 项目管理员 | 管理项目、删除项目、管理项目成员 |

第一版采用单用户本地模式：所有项目均归属于当前本地所有者，角色表仅用于说明后续多人版权限。登录、成员管理和跨用户隔离均为 P2 能力。

### 2.2 权限规则

- 用户只能查看自己创建的项目；
- 删除项目需要二次确认；
- 修复代码必须经过用户确认后才能生成新版本；
- 扫描结果只读保存，不允许直接篡改；
- 原始代码版本不可被修复版本覆盖。

## 5. M02 网页项目导入

### 5.1 上传方式

支持以下方式：

1. 上传 ZIP 文件；
2. 上传 HTML 文件；
3. 选择系统内置示例项目。

### 5.2 文件校验

系统必须校验：

- 文件类型；
- 文件大小；
- 是否包含 HTML 入口文件；
- 文件是否能够解压；
- 项目中是否包含绝对路径、`..` 路径穿越或符号链接；
- 是否仅包含白名单内的网页资源类型；
- 文件编码是否可读取。

MVP 限制如下：

- ZIP 压缩包不超过 20 MB；
- 解压后总大小不超过 100 MB；
- 文件总数不超过 500；
- 允许 HTML、CSS、JS、JSON、SVG、PNG、JPG、JPEG、GIF、WebP、字体文件及必要的文本资源；
- 拒绝可执行文件、脚本解释器文件、软链接和嵌套压缩包。

### 5.3 导入结果

导入成功后显示：

- 文件数量；
- HTML 页面数量；
- CSS 文件数量；
- JavaScript 文件数量；
- 图片数量；
- 默认入口文件；
- 项目目录树。

### 5.4 导入失败处理

| 场景 | 提示 |
|---|---|
| 文件格式不支持 | 请选择 ZIP 或 HTML 文件 |
| 文件过大 | 文件不能超过系统限制 |
| 没有 HTML 入口 | 未找到可预览的网页入口文件 |
| 解压失败 | 文件可能损坏，请重新上传 |
| 编码异常 | 无法读取部分文件，请检查编码 |

### 5.5 验收条件

- 合法 ZIP 能够成功导入；
- HTML、CSS、JavaScript 路径关系保持不变；
- 导入后的项目能够在预览页打开；
- 非法文件、超限文件和危险路径均不会被解压或执行；
- 导入失败不会产生残留项目。

## 6. M03 网页预览

### 6.1 页面功能

- 在隔离环境中加载网页；
- 支持桌面端预览；
- 支持移动端宽度预览；
- 支持刷新；
- 支持选择入口页面；
- 支持查看页面 URL 和加载状态。

预览与扫描必须在一次性浏览器上下文中运行：默认阻断外网、局域网和回环地址请求，禁用下载能力，并限制页面加载与脚本执行时长。系统不得向被测网页注入密钥、Cookie、宿主机路径或环境变量。

### 6.2 预览状态

网页预览状态包括：

- 未加载；
- 加载中；
- 加载成功；
- 加载异常；
- 页面脚本错误；
- 页面超时。

### 6.3 验收条件

- 导入成功的示例项目能够正常预览；
- 页面加载异常时展示错误原因；
- 预览环境与扫描环境使用相同的网页版本；
- 外部资源加载失败不会导致整个系统崩溃。

## 7. M04 扫描任务管理

### 7.1 启动扫描

用户可以选择：

- 当前项目全部页面；
- 指定页面；
- 扫描规则范围；
- 是否执行 AI 分析；
- 是否执行键盘操作测试。

默认开启全部 P0 规则，AI 分析和键盘测试作为默认开启选项。

MVP 不实现网页爬虫。所谓“全部页面”仅指项目中由用户勾选或系统从入口文件静态发现的 HTML 文件；无法静态发现或依赖路由运行时生成的页面需由用户手动选择。

### 7.2 扫描阶段

扫描任务按以下阶段执行：

1. 文件检查；
2. 网页启动；
3. DOM 解析；
4. CSS 分析；
5. 基础规则检测；
6. 页面截图；
7. 键盘交互检测；
8. AI 语义分析；
9. 结果汇总；
10. 评分计算。

### 7.3 扫描任务状态

- 等待中；
- 执行中；
- 已完成；
- 部分完成；
- 已失败；
- 已取消。

### 7.4 扫描进度页面

必须展示：

- 当前阶段；
- 总进度百分比；
- 已处理页面数；
- 已发现问题数；
- 已耗时；
- 取消按钮；
- 失败日志入口。

### 7.5 验收条件

- 扫描过程不会阻塞前端页面；
- 刷新页面后仍可以查询任务状态；
- 扫描失败时保留失败原因；
- 任务完成后自动跳转到结果页；
- 同一版本可以重复扫描并生成独立记录。

## 8. M05 基础规则检测

### 8.1 检测规则清单

| 规则编号 | 规则名称 | 检测方式 | 修复模式 |
|---|---|---|---|
| R001 | `img` 缺少 `alt` 属性 | DOM 结构；空 `alt` 的合理性仅作 AI 提示 | 仅生成候选 alt，需人工确认 |
| R002 | 表单控件缺少可访问名称 | DOM 关联关系 | 可关联已有可见标签；其他情况仅建议 |
| R003 | 按钮和链接缺少可访问名称 | DOM 结构；名称是否清楚为 P1 AI 提示 | 仅生成候选名称，需人工确认 |
| R004 | 页面语言声明缺失 | `html[lang]` 属性 | 可在用户确认语言后模板修复 |
| R005 | 标题层级风险 | DOM 结构 | 仅建议，不自动修改标题标签 |
| R006 | 文字颜色对比度不足 | 仅计算纯色前景与纯色背景 | 仅生成颜色建议，不自动应用 |
| R007 | 键盘焦点可达性与可见性风险 | 受限浏览器交互 | 仅对缺失焦点样式提供模板建议 |
| R008 | 重复 ID 或 ARIA 引用目标不存在 | DOM 结构 | 不自动修复 |

### 8.2 规则输出格式

每个检测结果至少包含：

```json
{
  "ruleId": "R001",
  "source": "rule",
  "title": "图片缺少替代文本",
  "severity": "high",
  "status": "failed",
  "page": "index.html",
  "selector": "main > img:nth-child(2)",
  "message": "该图片没有提供可供屏幕阅读器使用的替代文本",
  "evidence": [],
  "fixMode": "suggestion",
  "confidenceBand": "deterministic"
}
```

### 8.3 规则执行要求

- 规则检测结果必须可重复；
- 相同网页版本和相同规则配置应得到一致结果；
- 每条结果都必须关联页面和元素；
- 规则异常不得导致整次扫描失败；
- 不支持判断的项目标记为“需人工复核”。

## 9. M06 页面交互检测

### 9.1 键盘导航测试

系统在固定的测试路径上模拟键盘操作，至少检查：

- Tab 是否能够进入可交互元素；
- Shift+Tab 是否能够返回；
- 焦点是否可见；
- 对内置示例弹窗，检查打开后焦点是否进入弹窗；
- 对内置示例弹窗，检查 Esc 是否能够关闭弹窗；
- 是否存在键盘无法到达的按钮或链接。

### 9.2 页面截图

系统在扫描时保存：

- 页面完整截图；
- 关键区域截图；
- 问题标注截图；
- 修复后对比截图。

### 9.3 元素定位

每个问题应尽量提供以下定位信息：

- CSS Selector；
- XPath；
- HTML 代码片段；
- 页面坐标；
- 页面截图区域。

系统只能证明“在已执行路径上观察到的焦点行为”，不能据此声称所有功能均可通过键盘完整操作。

### 9.4 验收条件

- 系统可以自动完成 Tab 导航；
- 无法聚焦的元素能够被记录；
- 问题详情页可以定位到对应元素；
- 页面截图与当前扫描版本一致。

## 10. M07 AI 语义分析

### 10.1 P0 规则解释与 P1 AI 分析输入

P0 规则命中后必须使用模板生成中文问题说明、影响说明和通用整改方向；该步骤不依赖外部 AI 服务。

AI 分析模块可以接收：

- HTML 片段；
- DOM 上下文；
- CSS 样式；
- 页面截图；
- 元素周边文本；
- 基础规则检测结果；
- 键盘交互结果。

### 10.2 AI 分析任务

以下为 P1 冲奖能力；基础规则扫描即使 AI 服务不可用也必须完成：

1. 判断图片替代文本是否表达图片真实含义；
2. 判断按钮或链接名称是否清楚；
3. 判断页面标题是否符合页面内容；
4. 判断表单提示是否足够明确；
5. 提示视觉顺序和 DOM 顺序可能存在明显差异，该项必须人工复核。

### 10.3 AI 输出要求

AI 输出必须结构化，包含：

- 结论；
- 置信度等级（高、中、低）；
- 判断依据；
- 关联元素；
- 推荐动作；
- 是否建议自动修复。

置信度等级仅表达模型自身不确定性；在完成校准实验前，前端不展示未校准的小数概率。

AI 无法确定时必须返回：

> 需要人工复核

禁止将低置信度的判断直接标记为确定问题。

### 10.4 AI 解释展示

前端需要将 AI 结果转换成普通用户可理解的表达，不直接展示复杂模型输出。

示例：

> 该图片的替代文本为“图片”，无法说明图片的具体内容。系统建议候选文本“校园图书馆正门照片”；请开发者核对图片实际用途后再应用。

## 12. M09 AI 修复方案

### 12.1 支持的修复类型

第一版按风险分为三类：

| 修复类别 | 支持范围 | 应用规则 |
|---|---|---|
| 低风险模板修复（P0） | 用户确认页面语言后补充 `html lang`；将已有可见文本关联到已有表单控件；补充缺失的焦点样式 | 展示 Diff 后由用户确认应用 |
| AI 候选修复（V0.4.0 保留） | R001 图片 alt；R003 按钮、链接及 `role=button/link` 名称 | 用户编辑候选文本、审阅最小属性 Diff 并明确确认后才可应用；R009 禁止生成补丁 |
| 仅提示（P0/P1） | 标题层级、复杂 ARIA、键盘行为、阅读顺序 | 不生成可应用补丁 |

### 12.2 修复生成流程

1. 用户在问题详情页点击“生成修复”；
2. 系统读取与当前问题绑定的 AI 证据并预填候选文本；
3. 用户编辑候选文本，或为 R001 明确选择装饰性图片；
4. 系统通过浏览器选择器与 Jsoup 源码位置校验目标，只向目标开始标签插入属性；
5. 页面展示代码 Diff；
6. 用户确认或拒绝；
7. 确认后生成新版本；
8. 自动启动复测。

### 12.3 修复限制

- 默认只允许修改与问题直接相关的文件；
- 不允许删除整个页面或大范围重写项目；
- 修复必须生成 Diff；
- 修复前必须保存原始版本；
- AI 候选修复无论置信度高低都不能跳过用户确认；
- 只有高/中置信度的 R001/R003 AI 证据展示可应用入口，低置信度只保留建议；
- 内容图片 alt 为 1–300 字符；装饰图片必须由用户明确选择并写入 `alt=""`；R003 名称为 1–120 字符并写入 `aria-label`；
- 动态元素、选择器不唯一、已有目标属性或源码位置无法确认时拒绝生成补丁；
- 自动应用前必须先在临时副本完成语法校验；
- 对 alt、颜色、标题、ARIA 和键盘行为的修改不得以“自动修复成功”作为最终结论；
- 修复失败时保留原版本不变。

### 12.4 验收条件

- 用户能够查看修改前后代码；
- 用户能够拒绝修复；
- 用户能够回滚已确认修复；
- 修复后能够自动复测；
- 修复不会覆盖原始项目。

## 14. M11 修复后自动复测

### 14.1 复测范围

修复后沿用原扫描的页面、规则和键盘测试配置，强制关闭 AI，并检查：

- 原问题是否消失；
- 是否产生新的高风险问题；
- 页面是否能够正常加载；
- 关键交互是否仍然可用；
- 页面视觉是否发生异常变化。

复测不再次调用 AI。结果必须分别表达“基础规则已消除”和“语义已人工确认”；不得表述为模型已再次验证语义或完整 WCAG 验证。

### 14.2 复测结果

复测结果分为：

- 修复成功；
- 部分修复；
- 修复失败；
- 引入新问题；
- 无法判断，需要人工复核。

## 15. M12 内部风险分与结果对比

### 15.1 内部风险分

系统展示的是内部风险分，不是官方合规评分，也不是 WCAG 符合性声明。默认计算方式为：

```text
内部风险分 = max(0, 100 - 10 × 已确认高风险问题数 - 4 × 已确认中风险问题数 - 已确认低风险问题数)
```

基础规则命中的问题默认计入；AI 语义提示在人工确认前不计入。评分公式、规则版本和扫描配置必须随报告保存，保证前后版本可比较。

### 15.2 前后对比

必须支持展示：

- 总问题数变化；
- 高、中、低风险问题变化；
- 各类问题变化；
- 自动修复数量；
- 人工复核数量；
- 内部风险分变化；
- 页面截图变化。

### 15.3 验收条件

- 至少存在一个可重复的“修复前—修复后”示例；
- 修复后问题数量能够真实变化；
- 所有统计数字来自扫描结果；
- 对比结果可以导出到报告。

## 19. 关键接口需求

### 19.1 创建项目

```http
POST /api/projects
```

请求参数：

```json
{
  "name": "校园门户无障碍检测",
  "description": "用于比赛演示的示例项目",
  "type": "campus"
}
```

### 19.2 上传项目

```http
POST /api/projects/{projectId}/upload
```

返回：

```json
{
  "projectId": "project-001",
  "entryFile": "index.html",
  "fileCount": 24,
  "pageCount": 3
}
```

### 19.3 启动扫描

```http
POST /api/projects/{projectId}/scans
```

请求参数：

```json
{
  "pages": ["index.html"],
  "enableAi": true,
  "enableKeyboardTest": true,
  "rules": ["R001", "R002", "R003", "R004", "R005", "R006", "R007", "R008"]
}
```

### 19.4 查询扫描结果

```http
GET /api/scans/{scanId}/findings
```

### 19.5 生成修复方案

```http
POST /api/findings/{findingId}/fix-patches
```

模板请求继续使用 `{ "language": "zh-CN" }`；AI 请求使用 `{ "aiEvidenceId", "candidateText", "decorative" }`。证据必须属于当前问题且规则为 R001/R003。相同待审补丁直接返回，不同候选内容返回 `PATCH_ALREADY_PENDING`。

### 19.6 应用修复

```http
POST /api/fix-patches/{patchId}/apply
```

AI 候选补丁必须提交 `{ "reviewAccepted": true }`。成功后记录最终文本、模型来源和确认时间，创建 `AI_PATCH` 不可变版本并自动复测。

### 19.7 启动复测

```http
POST /api/versions/{versionId}/rescan
```

### 19.8 导出报告

```http
GET /api/scans/{scanId}/report?format=pdf
```

## 20. 异常处理

### 20.1 网页加载失败

系统保留加载日志，并提示：

- 入口文件不存在；
- 页面脚本异常；
- 外部资源加载失败；
- 页面加载超时。

### 20.2 AI 服务失败

系统应：

- 保留基础规则检测结果；
- 标记 AI 分析未完成；
- 支持单独重试 AI 分析；
- 不影响报告导出；
- 不自动生成未经验证的修复代码。

报告中必须区分“基础规则扫描完成”和“AI 分析未执行或失败”，不得将前者表述为完整扫描完成。

### 20.3 修复失败

系统应：

- 保留原始版本；
- 删除未通过校验的临时版本；
- 展示错误原因；
- 允许用户返回问题详情页重新生成方案。

### 20.4 报告生成失败

系统应：

- 记录失败日志；
- 支持重新生成；
- 提供 JSON 结果下载作为备用方式。

## 16. V0.4.0 功能增量（现行基线）

### 16.1 新增页面与交互

- 新增 `/scans/:scanId/interaction`，包含页面选择器、“键盘焦点路径 / 阅读顺序”两个视图。
- 截图编号标记必须与文字表格同步；焦点视图可切换正向与反向路径，阅读顺序视图可切换 DOM 与视觉序列。
- R007/R009 问题详情复用同一证据组件并聚焦对应元素或冲突证据。

### 16.2 人工复核

- `CONFIRM_RISK` 将 R009 转为已确认中风险；`DISMISS_FALSE_POSITIVE` 将其排除且要求 5–1000 字理由；`NEEDS_FOLLOW_UP` 仅记录本次并保持待复核。
- 确认与误报形成项目级精确复用策略。后续人工操作可覆盖旧结论，所有历史必须保留。
- 源码、可访问名称、相关样式、几何顺序或证据指纹变化后必须重新复核。

### 16.3 接口和统计

- `GET /api/scans/{scanId}/analysis-traces?type=&pagePath=` 返回页面焦点或阅读顺序轨迹。
- `POST /api/findings/{findingId}/reviews` 要求 `Idempotency-Key`，请求为 `{action, comment}`。
- 问题列表支持 `status`、`source` 过滤和 `sort=severity|review` 白名单排序。
- `ScanTask` 增加 `reviewCount`；报告快照增加轨迹、复核历史、复用标记和待复核统计。

### 16.4 V0.4.0 完成定义

原“8 类基础规则”验收项升级为 R001–R009。系统必须在 AI 关闭或失败时完成焦点轨迹、R009 候选、人工复核、精确结论复用和 PDF/JSON 导出；10 页静态项目单并发目标仍为 60 秒内完成。
