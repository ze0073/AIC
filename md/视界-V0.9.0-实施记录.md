# V0.9.0 网站部署、检测与修复：实施与本机验收

更新日期：2026-10-03（北京时间）。版本：`0.9.0-SNAPSHOT`。

## 交付状态

注册 → 导入源码 → 隔离部署 → 自动检测 → 应用源码修复 → 部署复测 → 用户确认更新 → 应用回退，已完成本机实际闭环。私有仓库的凭据处理已实现并验证，真实授权私有仓库导入仍需提供仓库访问凭据后验收。

### 已实现

- 自助注册：用户名、密码、图片验证码、频率限制；沿用密码加密和会话。
- 平台管理员管理账号及额度；项目管理员管理项目成员。取消新账号自动加入旧项目的行为，管理员也遵守其配置的项目额度。
- 网站工作区和导入向导：ZIP / HTML、公开 / 私有 Git；固定源码版本、仓库提交、配置、镜像摘要。私有凭据和环境变量通过专用表单加密保存，不回显。
- 静态网页、React、Vue、Node.js、Java / Spring Boot（Maven）、Python、附带 Dockerfile 的自定义项目；支持独立前后端目录、同源接口转发、MySQL / PostgreSQL。
- 检测修复或长期托管用途切换；测试环境默认 24 小时，正式版本持续运行。
- 独立执行进程、持久队列及事件：导入、构建、启动、健康检查、检测、可访问；实时事件和轮询恢复，取消、重试、日志、重启恢复。
- 修复实际创建新源码版本，确认差异后自动部署，并沿用原检查范围复测；展示修改原因、收益、前后证据和防复发建议。
- 更新先启动并检查新版本，再切换网站入口；失败保留原版本。回退恢复应用镜像与配置，数据库不随应用回退。
- 下载源码、SQL 备份和完整数据备份。完整 ZIP 包含 `website-files.tar.gz`、可选 `database.sql` 和说明；文件来自该环境的 `/data`，停止后仍可下载。
- 手机导航、主要操作和历史版本折叠；失败给出下一步建议，原始日志按需展开。

### 运行与隔离

- 管理地址：`http://127.0.0.1:8080`；网站独立 `.localhost:8090` 地址；执行器健康端口 `18091`。
- Docker Desktop Linux Engine 29.8.0，本机引擎约 16 GB 内存、24 CPU。
- 用户应用：独立内部网络、数据卷和数据库，普通用户、只读根目录、删除能力、禁止提权；应用资源限制 1 GB 内存、1 CPU、128 进程。无宿主目录、Docker 接口挂载。
- 独立 BuildKit：2 GB / 2 CPU；依赖入口校验公网目的地址，自定义构建不授予宿主网络或特权权限。
- 正式数据库与测试副本分离。正式目标拒绝写入、上传流程、主动安全和负载检查；测试须沿用目标的明确授权。
- 管理会话和预览凭据不传给网站；网站自己的会话保留。私有预览校验项目成员权限。
- 新旧问题按网站身份、页面路径和规则 / 用例关联，不受版本域名变化影响。复测完整性、原问题消失、页面可用、无新增高风险和健康检查均参与发布校验，缺失证据不能通过。
- V13 / V14 已迁移：账号角色 / 额度、网站、源码导入、部署、加密密钥、数据库资源、持久事件、执行器心跳、数据库结构指纹；既有项目、修复与报告保留。

## 验收中修正的问题

1. Docker 信息输出截断造成误报未就绪，改为读取必要字段；执行器就绪通过独立心跳判断。
2. 本机网络改写 DNS、代理连接和内部网络端口发布问题，改为受控公网解析 / 转发和可信入口容器。
3. Windows 数据库参数引用导致结构查询失败，改为受控 SQL 输入；两种数据库实测通过。
4. Docker 重启会改变动态访问端口，执行器恢复时重新读取端口。入口暂未恢复时返回明确状态。
5. 单用户短负载从 0 用户爬升未产生请求，改为从 1 用户开始，保留“无有效样本不能通过”的校验。
6. 新版本健康检查按实际 90 秒时限执行；发布失败不切换原入口，错误日志及提示均脱敏。
7. 修复自动部署失败显示具体原因；发布后停止对应测试环境，保留证据与数据，不长期占用测试额度。

## 复现与维护

```powershell
# 根目录：启动 / 状态 / 停止平台
./start-demo.ps1 -TimeoutSeconds 120
./status-local.ps1
./stop-local.ps1

# 后端：启用真实浏览器、Docker 回归
cd backend
. ../runtime-common.ps1
mvn '-Dplaywright.tests=true' '-Ddocker.tests=true' test

# 前端
cd ../frontend
npm test
npm run build
```

集成验收脚本依赖已启动的平台以及本机样例账号，并会创建网站、调整样例额度、应用修复和发布样例网站；用于开发验收，不对真实项目执行。部分闭环脚本按既有验收状态继续操作；状态与任务编号记录在 `output/hosting-fixtures/state.json`。
