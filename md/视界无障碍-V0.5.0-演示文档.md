# V0.5.0 比赛演示与验收

## 演示前检查

1. 首次联网安装 Java 21、Node、Maven、Docker 和 Chromium，并完成前后端构建。
2. 执行 `start-demo.ps1`；它使用现成 JAR，不下载依赖。执行 `status-local.ps1` 确认本项目进程、应用健康及 MySQL 状态。
3. 打开 `http://localhost:8080`，新安装两个校园示例。保留旧项目以便回顾，不重置数据。
4. 默认关闭 AI。若展示 AI，按既有提示单独授权；未配置、未授权或失败均可继续离线演示。

## 6–8 分钟真实操作讲稿

| 时间 | 操作 | 讲解重点 |
| --- | --- | --- |
| 0:00–0:45 | 安装图书馆示例，进入演示流程 | 六步来自真实业务记录，URL 固定版本和扫描 |
| 0:45–1:45 | 开始离线扫描，打开证据 | R001–R009 无需 AI；自然顺序可以没有 R009 候选 |
| 1:45–3:00 | 选择 R004，生成模板 Diff，确认应用 | 原始版本不变，新版本自动沿用原配置复测 |
| 3:00–4:00 | 返回演示，打开前后证据对照 | 对照截图、DOM 和 Diff；未再检出与已确认的目标修复分别展示 |
| 4:00–5:30 | 切换已完成扫描的课程示例，打开 R009 | CSS 重排只是候选；依据证据人工确认或填写理由驳回 |
| 5:30–6:30 | 生成报告快照，继续改变复核结论 | 旧报告保持原结论，新快照记录最新复核历史 |
| 6:30–8:00 | 导出同一快照的 PDF 与 JSON | 相同快照 ID、时间、哈希与统计；内部风险分越高，检出风险越少 |

课程示例建议在正式讲解前完成首次扫描，现场复核和快照生成仍执行真实操作。需要从零展示时可多留一分钟扫描时间。

## 降级操作

- AI 不可用：保持关闭，使用模板修复和本地交互证据。
- 扫描部分失败：查看已保存证据和错误说明；对比不计算改善数量，处理原因后创建新扫描。
- 页面加载失败：使用重试按钮，URL 中保留演示和快照选择。
- PDF 渲染失败：保留快照 ID，先导出 JSON；浏览器恢复后从同一快照重试 PDF。
- 历史扫描缺少页面范围：可看证据，不作数量改善结论；重新扫描后比较。
- 端口占用或进程身份不符：脚本停止并说明原因，不终止无关进程。

## 固定报告与兼容

`POST /api/scans/{scanId}/report-snapshots` 必须带 `Idempotency-Key`。相同扫描与相同键返回同一快照；换键生成新快照。

列表接口 `GET /api/scans/{scanId}/report-snapshots` 支持回看历史。读取和下载分别使用 `/api/report-snapshots/{snapshotId}` 与 `/export?format=pdf|json`。报告正文在一致的数据库读取视图内冻结，导出失败不会修改正文。

旧 `/report-snapshot` 与 `/report` 接口选择最新快照，无快照时创建首份；通过 `X-Report-Snapshot-Id` 标明结果归属。要获得复核后的新内容，请显式创建新快照。已保存的 V0.4.0 报告工件不重写。

## 验收与结束

运行 `verify-demo.ps1` 连续验收两轮两个示例，检查真实扫描、负例/正例、模板修复、复核变化、快照不可变和报告复用。另运行前后端测试，验证比较边界、浏览器规则和 UI。

实测记录保存到 `output/v050/`。演示结束执行 `stop-local.ps1`，仅停止本项目进程和数据库，保留项目及报告数据。
