# 视界向导首版：实施与验收

日期：2026-10-04。保留现有 `0.9.0-SNAPSHOT` 版本、项目助手和历史报告接口。

## 已实现体验

- 登录后的全站布局挂载本地 SVG 二维机器人，提供待机、回应、执行、完成和异常状态。灰绿、荧光黄沿用平台配色。
- 桌面右侧面板、移动端底部抽屉；第一次进入展示欢迎和五类目标，选择或跳过后服务端保存偏好。之后默认收起，入口显示继续未完成流程。
- 带我操作：打开原页面，通过稳定 `data-guide` 标识定位 Ant Design Tour；控件缺失时提供文字说明。结束导览、关闭面板后恢复入口焦点。
- 帮我办理：共享业务服务准备具体操作，卡片显示冻结资源、配置、检测计划或代码差异，用户点击确认才执行。聊天中的“确认”“开始”不能执行业务操作。
- 草稿、目标、操作方式、资源关联、对话和操作回执保存在个人会话中；切换网站或目标保留原流程，可从历史列表恢复。
- 上传、仓库凭据和环境变量继续使用专用表单。凭据不进入向导对话、个人草稿或向导模型摘要。
- 复用业务 SSE，并每 3 秒重新读取真实资源；页面刷新或断线恢复后根据业务资源推导当前步骤。
- 语音默认静默，每次由用户手动播放；支持暂停、继续和停止。中文声音缺失时显示文字提示，关闭面板、退出登录布局时停止播报。
- 规则模式不依赖外部模型。Qwen 仅增强意图与下一步建议，必须取得脱敏摘要发送同意；无效输出或请求失败后继续规则流程。

## 首版业务路径

| 目标 | 已接入能力 |
| --- | --- |
| 部署我的网站 | 创建网站工作区、ZIP／HTML 上传、HTTPS 仓库导入、运行设置、冻结部署确认、既有自动检测跟踪、失败环境重试、正式更新确认 |
| 检查网站质量 | 项目／登记目标／方案版本选择、现有推荐与同范围基线、固定检测计划确认、任务和各模块运行证据、业务取消接口 |
| 修复发现的问题 | 选择问题和对应源码、规则补丁／经同意的 AI 候选、手动源码编辑入口、完整差异审阅、共享应用部署复测编排、复测报告入口 |
| 查看检测结果 | 运行和快照选择、优先级说明、具体问题证据入口、生成不可变快照、从同一快照解释并导出 PDF／JSON |
| 了解平台 | 功能目录、所需材料与入口，各流程示例说明 |

停止、回退和删除由原网站工作区办理；向导保存流程并重新读取结果。外部网站的修复代码仍需用户下载部署，之后使用原修复页的在线复测流程。

## 数据和执行约束

Flyway V17 新增 `guide_preferences`、`guide_sessions`、`guide_messages`、`guide_actions`，没有迁移或替换旧项目助手表。

新增接口位于 `/api/guide`：个人偏好 GET／PUT、会话列表 GET／创建 POST、会话 GET／PATCH、消息 POST、冻结操作 confirm／cancel POST。

个人会话仅所有者可访问；关联项目、网站、源码版本、目标、方案、任务、问题、修复和报告继续通过原项目权限验证。浏览器提交的上下文必须由服务端核对。

操作有效期为 25 分钟。预览保存资源参数、版本、哈希和状态指纹；确认重新核对权限、源码、配置、任务和正式版本。幂等确认返回已保存回执，不重复创建版本、部署或检测。业务失败回滚后另行保存失败回执，用户重新准备操作。

`RepairWorkflowService` 将原控制器的应用修改与自动部署复测编排提取为共享服务。正式更新从本次复测环境准备操作，发布后的正式回执不会被旧测试环境覆盖。

前端全量测试原 18 个文件、83 项通过；随后新增控件缺失和退出清理两项，并重跑向导 11 项全部通过。最终合计 85 项。生产构建通过；现有主包体积提示仍存在。

后端全量测试原 183 项：176 项通过、7 项按原配置跳过、失败和错误为 0；随后新增两项修复发布衔接测试，向导相关 18 项全部通过。最终合计 185 项，其中 7 项为原有需显式启用的浏览器／Docker 测试。本次独立 HTTP 验收实际执行了 Docker 构建、Chromium 检测和 PDF 生成。

隔离 HTTP 验收脚本：`tools/verify-guide.mjs`。使用生成的独立 MySQL schema、存储目录、账号和端口，完整检查：

1. V17 迁移及个人偏好隔离。
2. 会话／操作隔离，工作区创建确认重放。
3. 草稿恢复、操作方式切换、聊天执行边界和版本冲突。
4. ZIP 导入、25 分钟预览过期处理。
5. 运行配置变化后拒绝旧冻结操作。
6. 真实部署及自动检测只启动一次，恢复真实进度。
7. 固定 CHECK 操作、重复确认和各模块运行恢复。
8. 规则补丁、差异审阅、应用后自动部署复测只创建一次。
9. 从修复流程确认正式更新，验证发布结果。
10. 解释、JSON 和 PDF 使用同一份固定快照。
11. Qwen 非法结构化输出回退、配置保留、敏感输入不外发。
12. 公共 Git 仓库导入成功并固定提交。
13. V17 后旧项目助手仍可创建和读取。

Qwen HTTP 验收使用本地可控响应，不调用真实付费模型；格式、异常和敏感输入行为有确定性证据。真实 Qwen 服务质量与实际设备语音听感尚未验收。公共仓库使用 `octocat/Hello-World`；没有使用真实私有仓库令牌。

## 本机复验

先按 README 配置 Java、Node、MySQL、Docker、Chromium 和 Git，构建前端及后端，然后运行：

```powershell
node tools/verify-guide.mjs
```

默认端口为 18082／18090；已占用时脚本拒绝启动。可通过 `GUIDE_QA_PORT`、`GUIDE_QA_GATEWAY` 和 `GUIDE_QA_JAR` 指定独立验收端口与包。`GUIDE_QA_HOLD=1` 在验收通过后保留服务用于浏览器交互；未设置时完成后停止隔离服务和该脚本创建的运行环境，保留验收数据与证据。

规则引导与现有业务流程可用性是首版验收范围。“离线”指不连接外部模型；源码仓库、外部网站检测和首次构建依赖下载仍需要对应网络条件。

参考实现接口：[Ant Design Tour](https://ant.design/components/tour/)、[SpeechSynthesis](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis)。
